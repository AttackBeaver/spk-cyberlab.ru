Расширенный план реализации полноценной песочницы (SPK CyberLab)
Цель
Создать интерактивную среду для отработки практических навыков по информационной безопасности, криптографии, базам данных и программированию, аналогичную профессиональным онлайн-тренажёрам (TryHackMe, PortSwigger, SQLZoo и др.).

I. Модели данных (расширение существующих)
Добавить в SandboxTask:

templateId – ссылка на предопределённый шаблон (если задание создано из шаблона).

config – JSON-конфиг для настройки задания (например, для SQL: структура БД, для XSS: целевой URL, для фишинга: содержание письма).

hint – текст подсказки (может быть несколько уровней).

expectedReport – эталонный отчёт (для автоматической проверки отчёта).

Создать модель SandboxTemplate:

id, name, description, type (SQL_INJECTION, XSS, PHISHING, CODE, DATABASE, CUSTOM).

configSchema – JSON-схема для настройки (какие параметры можно менять).

defaultConfig – базовый конфиг.

previewHtml – HTML-макет для демонстрации (для предпросмотра).

Добавить модель SandboxStudentReport (отчёт студента):

id, attemptId (связь с попыткой), text (текст отчёта), score (оценка преподавателя), reviewedBy, reviewedAt.

Добавить поле isManualReview в SandboxTask – если задание требует ручной проверки (например, отчёт).

II. Система шаблонов и конструктор
Разработать набор готовых шаблонов:

SQL Injection (поиск): макет сайта с поисковой строкой, уязвимой к ' OR 1=1 --. Конфиг: таблицы, поле для инъекции.

SQL Injection (аутентификация): форма входа, уязвимая к admin' --.

XSS (комментарии): макет блога с формой добавления комментария, уязвимой к <script>alert(1)</script>.

XSS (рефлексивный): параметр URL, отражающийся на странице.

Фишинг: письмо или веб-страница с признаками фишинга (поддельный URL, запрос пароля).

Программирование (Python): задача с тестами (ввод-вывод).

Базы данных: схема БД, запросы SELECT, JOIN, GROUP BY.

Интерфейс конструктора для преподавателя:

Выбор шаблона.

Настройка параметров через форму (поля, таблицы, ожидаемый результат, подсказки).

Превью макета до сохранения.

Возможность загружать свои HTML/CSS/JS файлы (для кастомных макетов).

III. Эмуляция выполнения заданий
SQL-инъекции и работа с БД:

Встроенная in-memory SQLite или PostgreSQL (в контейнере) с предзаполненными данными.

При выполнении задания студент вводит запрос, он выполняется на тестовой БД, результат возвращается.

Проверка: ожидается определённый результат (например, данные пользователя admin) или наличие ошибки.

XSS и фишинг:

Макет рендерится во встроенном iframe.

Студент взаимодействует с макетом (вводит данные), система анализирует ввод на наличие вредоносного кода.

Проверка: автоматическая (обнаружение паттернов) или ручная (преподаватель проверяет отчёт).

Программирование (код):

Студент пишет код в редакторе (например, Python, JavaScript).

Код выполняется в изолированной среде (Docker-контейнер с ограничениями).

Результат (вывод) сравнивается с ожидаемым.

Кастомные задания:

Преподаватель загружает свой проверочный скрипт (Node.js/Python).

Система запускает скрипт с ответом студента и возвращает результат (проход/не проход).

IV. Фронтенд: страница выполнения задания (студент)
Интерактивный макет:

Отображение HTML-макета (если есть) в iframe с возможностью взаимодействия.

Для SQL: терминал (textarea с подсветкой синтаксиса) и кнопка "Выполнить", вывод результата.

Для XSS/фишинга: макет с формами, поле для ввода.

Поле для ответа:

В зависимости от типа: текстовое поле (для отчёта), редактор кода (для программирования), терминал (для SQL).

Подсказки:

Постепенное раскрытие подсказок (по нажатию кнопки или по времени).

Таймер (если установлен).

Отправка ответа/отчёта:

Кнопка "Отправить" – сохраняет попытку и/или отчёт.

Для ручной проверки: отправка отчёта на проверку преподавателю.

V. Фронтенд: конструктор для преподавателя
Пошаговый мастер:

Шаг 1: выбор типа задания (шаблон).

Шаг 2: настройка параметров (поля, таблицы, текст макета).

Шаг 3: предпросмотр и сохранение.

Загрузка файлов:

HTML, CSS, JS для макета.

Скрипты проверки (для кастомных заданий).

Управление шаблонами:

Просмотр, редактирование, удаление шаблонов (только ADMIN).

VI. Бэкенд: расширение логики проверки
Модуль sandbox-executor:

Singleton для управления изолированными средами (Docker API или in-memory).

Выполнение SQL-запросов, выполнение кода, запуск проверочных скриптов.

Обработка отчётов:

Автоматическая проверка отчётов по ключевым словам (если задан expectedReport).

Ручная проверка: преподаватель выставляет оценку и комментарий.

Генерация отчётов для преподавателя:

Статистика по заданию: количество попыток, успешных/неуспешных, средний балл.

Список студентов с результатами, возможность экспорта в CSV.

VII. Интеграция и доработки
Геймификация:

Выдача достижений за выполнение определённого количества заданий полигона (например, "Первая инъекция", "Мастер XSS").

Логирование:

Запись всех действий в таблицу Log (старт, отправка, просмотр результатов).

Безопасность:

Изоляция кода (Docker) – для программирования.

Ограничение доступа к файловой системе, сети.

VIII. Поэтапная реализация (приоритеты)
Этап 1: SQL-интерактив – эмуляция выполнения запросов (база данных in-memory) + конструктор для SQL-заданий.

Этап 2: XSS и фишинг – макеты с формами и автоматическая проверка.

Этап 3: Программирование – выполнение кода в изолированной среде (Docker).

Этап 4: Отчёты и ручная проверка – добавление модели отчёта, интерфейс для преподавателя.

Этап 5: Аналитика – статистика и экспорт CSV.

Этап 6: Геймификация и логирование.

IX. Технические соображения
SQL-эмуляция: использовать sqlite3 в памяти (легко, не требует отдельного контейнера) или PostgreSQL в Docker.

Выполнение кода: использовать Dockerode (Node.js) для управления контейнерами (можно предварительно подготовить образы с Python, Node.js).

Безопасность: ограничить ресурсы контейнера (CPU, memory), время выполнения, запретить сетевой доступ.

Проверка XSS/фишинга: использовать библиотеки для парсинга HTML (cheerio) или регулярные выражения (но лучше ручная проверка).
