Шаги реализации полигона-песочницы (SPK CyberLab)
1. Проектирование моделей данных
SandboxTask – задание для полигона:

id, title, description, instructions, type (SQL_INJECTION, XSS, PHISHING, CODE, CUSTOM), difficulty, time_limit, attempts_limit, points, created_by (преподаватель/админ), created_at, updated_at.

SandboxTaskGroup – связь задания с группами (кто может выполнять):

id, task_id, group_id, assigned_at.

SandboxAttempt – попытка выполнения студентом:

id, task_id, user_id, answer (текст или код), score, status (PENDING, PASSED, FAILED, TIME_EXPIRED), started_at, completed_at, feedback (текстовый ответ системы).

SandboxEnvironment – настройки среды выполнения (для сложных заданий с кодом):

id, task_id, type (SQL, JS, PYTHON, CMD), image (ссылка на Docker-образ), parameters (JSON).

SandboxSession – сессия выполнения (для изоляции, если использовать Docker):

id, attempt_id, container_id, status (ACTIVE, COMPLETED, EXPIRED), created_at, expires_at.

Добавить в схему Prisma.

2. Бэкенд: CRUD для заданий полигона
Создание, редактирование, удаление, просмотр заданий (доступно TEACHER и ADMIN).

Типы заданий: предопределённые (SQL, XSS, код) + возможность кастомных (с проверкой через регулярные выражения, скрипты или шаблоны).

Конструктор заданий: форма с полями: название, описание, тип, сложность, время, попытки, баллы, а также поле для ввода "правильного ответа/паттерна" или кода проверки.

Эндпоинты: /api/sandbox/tasks (CRUD).

3. Бэкенд: назначение заданий группам
Эндпоинт для привязки задания к одной или нескольким группам.

Просмотр доступных заданий для студента (только те, что назначены его группе).

Список назначений для преподавателя/админа (управление доступом).

4. Бэкенд: выполнение задания (ядро песочницы)
Получение задания по ID (для студента) – проверка доступа.

Создание попытки (SandboxAttempt) при старте.

Проверка ответа:

Для простых текстовых/шаблонных – сравнение с эталоном.

Для SQL/кода – выполнение в изолированной среде (эмуляция или реальный контейнер).

Для кастомных – выполнение пользовательского скрипта проверки (песочница).

Ограничение по времени и попыткам.

Сохранение результата (баллы, статус, фидбек).

Реализация изоляции:

На первом этапе – эмуляция на уровне бэкенда (парсинг SQL, имитация выполнения, проверка паттернов).

В перспективе – реальные Docker-контейнеры (подготовка образов, запуск по требованию, таймауты).

5. Бэкенд: статистика и аналитика
Для студента: просмотр своих попыток, результатов, прогресса по заданиям.

Для преподавателя/админа: сводка по группе, по заданию, детализация каждой попытки (ответ, баллы, время).

Экспорт статистики в CSV (для преподавателя).

6. Фронтенд: интерфейс для студента
Страница со списком доступных заданий (по группам).

Страница выполнения задания: отображение условия, интерактивная форма (ввод текста, кода, выбор вариантов), таймер обратного отсчёта, кнопка отправки.

Отображение результатов после проверки (баллы, фидбек).

История выполненных заданий (статистика).

7. Фронтенд: интерфейс для преподавателя/админа (конструктор)
Страница создания/редактирования заданий (с выбором типа, настройками, полем для правильного ответа/паттерна).

Возможность загружать дополнительные файлы (скрипты проверки, SQL-скрипты, конфиги).

Страница управления назначениями: выбор задания, выбор групп, назначение.

Страница просмотра статистики: по заданиям, по группам, по студентам.

8. Расширяемость (возможность добавления новых типов через код)
Создать интерфейс/базовый класс для проверяющих модулей.

Регистрация новых типов в конфиге или через плагины.

Хранить логику проверки в отдельных файлах (например, checkers/sql-injection.js), чтобы можно было добавлять новые без изменения основного кода.

9. Интеграция с существующими модулями
Использовать существующую систему ролей, групп, аутентификации.

Привязать к достижениям (геймификация): выдавать бейджи за выполнение заданий полигона.

Логирование действий (таблица Log).

10. Тестирование и отладка
Написать тесты для проверки изоляции (безопасность).

Тестирование различных типов заданий.

Нагрузочное тестирование (если планируется много пользователей).

11. Документация
Инструкция для преподавателей по созданию заданий.

API-документация для интеграции.

Руководство пользователя для студентов.
